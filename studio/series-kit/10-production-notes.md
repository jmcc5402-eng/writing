# Template — Production Notes (draft handoff → review → adoption)

_Proven by: the `DRAFT-NOTES.md` / review / adoption chain that
carried three drafting waves. Its property worth keeping: every
change cites its authority by ID ("Snowflake R1; continuity E2"), so
revision is auditable instead of vibes._

---

## B. Review pass (critic, then the editorial three IN ORDER)

1. **Critic** — verdict up front; findings classified
   delivered / not delivered / new problem; every claim cites pages.
2. **Developmental** (structure) → 3. **Line** → 4. **Continuity
   LAST** (earlier passes invalidate it). Continuity findings
   classified contradiction / unestablished / deliberate, plus two
   lists: new canon established, open [TK]/[CHECK] markers.

Author rulings on findings become dated **[Canon decision]** entries
in the premise doc before the next drafting wave.

## C. The adoption pass (the step that closes the loop)

_A draft is UNADOPTED until the author reads the full set and says so.
Adoption is ONE pass that updates together:_

1. `manuscript.md` — the draft replaces canon text
2. `CHANGELOG.md` — the logged entry, applied
3. `THREADS.md` — v2 tags resolved; maps reflect the accepted text
4. the series ledger — cells updated to what the page now earns
5. banned-moves ledger — tics the reviews caught, appended

_Until adoption runs, every downstream doc tags the draft "(v2 draft /
unadopted)". Production lesson: this is the only stage with no agent
owner — it is the author's, and it must be scheduled, not assumed._

---

**Kit notes.**
- Drafts go to `drafts/YYYY-MM-DD/`, never into `manuscript/`.
  Chapter files named to sort: `ch01-<slug>.md`.
- [TK]s between beats, never at emotional peaks or inside dialogue.
- Chapters end on their own strongest beat — no trailer-voice.
